# 烧录固件流程

两条路线，我都走过。先说结论：**想调参走路线 B，图省事走路线 A。**

| 路线 | 做法 | 能否改参数 | 适用 |
|---|---|---|---|
| A | 直接烧作者合体固件 `firmware.bin` | 不能（模块被冻结） | 只想原样飞 |
| B | 烧官方纯净 MicroPython + 自己上传 9 个 .py | 能 | 想调 PWM、采样、参数 |

## 环境

| 项 | 值 |
|---|---|
| Python | 3.14（`C:\Users\周锐\AppData\Local\Python\pythoncore-3.14-64\python.exe`） |
| esptool | v5.6.0 |
| 串口 | COM4（以设备管理器实际显示为准） |
| 开发板 | 第三方 ESP32-C3 兼容板（丝印为准） |

安装 esptool：

```powershell
python -m pip install esptool
```

## 路线 A · 烧作者的合体固件

### 1. 先擦除

```powershell
python -m esptool --port COM4 erase-flash
```

### 2. 再烧写

```powershell
python -m esptool --port COM4 write_flash 0x0 "C:\大三上\宣怀\butterfly\Mech-Butterfly-main\0，固件\BLE\firmware.bin"
```

### 3. 看串口输出确认

烧完复位，串口会打印 `BLE 广播已启动`。
如果出现 `Device is busy`，**属正常现象**，不是烧失败——表示蓝牙正在广播，资源被占用。

### 注意：这条路调不了参数

作者这个合体固件把 `Kang_BLE.py` 烧进了内部文件系统，且**冻结模块优先于用户文件系统**。也就是说你在 Thonny 里改了同名文件也不会生效，甚至根本传不上去。想调参只能走路线 B。

## 路线 B · 官方纯净固件 + 自己上传代码（已验证走通）

### 1. 擦除

```powershell
python -m esptool --port COM4 erase-flash
```

### 2. 烧官方 MicroPython

```powershell
python -m esptool --port COM4 write_flash 0x0 "C:\大三上\宣怀\butterfly\Mech-Butterfly-main\0，固件\官方\ESP32_GENERIC_C3-20260824-v1.29.0.bin"
```

### 3. 用 Thonny 连上、确认版本

打开 Thonny → 运行 → 选择解释器 → MicroPython (ESP32) → 端口选 COM4。
连上后 Shell 里敲：

```python
import sys
print(sys.implementation)
```

看到 `v1.29.0` 就说明纯净固件烧好了。

### 4. 上传 9 个 .py 到板子根目录

要传的文件（飞控，来自 `2，程序\飞控\`）：

```
main.py
Kang_Flyer_Ornithopter.py
Kang_Sevor.py
Kang_Battery.py
Kang_Led.py
Kang_Espnow_FC.py
Kang_Utils.py
Kang_Queue.py
Kang_Mac.py
```

上传方法（**这里踩过坑**）：
- 必须在 **Thonny 左侧的"文件"面板**里操作，不是在 Windows 资源管理器里拖文件；
- 在文件面板右键目标 .py → `Upload to /` → 选板子根目录。

### 5. 验证

Shell 里敲：

```python
from Kang_Flyer_Ornithopter import Ornithopter
o = Ornithopter()
```

不报错就说明 9 个模块都 import 成功、舵机对象也建起来了。

## 踩过的死路（别重复）

| 现象 | 原因 | 解法 |
|---|---|---|
| `PermissionError(13)` | Thonny 占着 COM4，esptool 抢不到串口 | 先在 Thonny 里断开连接/关掉 Thonny，再跑 esptool |
| Thonny 固件对话框里选不到本地 bin | 新版 Thonny 该对话框只列官方在线固件，无本地文件入口 | 改用终端 esptool 烧本地 bin |
| 传上去的 .py 不生效 | 合体固件的冻结模块优先于文件系统 | 换成官方纯净固件再上传 |
| 拖文件到 Thonny 没反应 | 用错了操作方式 | 在 Thonny 左侧文件面板右键 `Upload to` |

## 固件版本对照

| 文件 | 大小 | 来源 | 能否调参 |
|---|---|---|---|
| `BLE\firmware.bin` | 1,691,712 B | 作者 | 否（冻结模块） |
| `ESPNOW\FC\*.bin` | 1,690,496 B | 作者 | 是 |
| `ESPNOW\RC\*.bin` | 1,692,656 B | 作者 | 是 |
| 官方 `ESP32_GENERIC_C3-20260824-v1.29.0.bin` | 1,754,736 B | MicroPython 官方 | 完全可控 |
