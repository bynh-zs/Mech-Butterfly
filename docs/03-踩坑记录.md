# 踩坑记录

按类型分三类：软件/工具、硬件/接线、认知误区。每条写清楚现象、原因、怎么绕过去。

## 一、软件与工具

### 1. esptool 报 PermissionError(13)

**现象**：跑 esptool 擦除或烧写，直接抛 `PermissionError(13): Permission denied`。

**原因**：Thonny 还连着 COM4，串口被独占，esptool 抢不到。

**解法**：先在 Thonny 里断开连接（或直接关掉 Thonny 进程），再跑 esptool。烧完要调试再重新连。

### 2. 新版 Thonny 的固件对话框没有本地 bin 入口

**现象**：Thonny → 运行 → 配置解释器 → 安装或更新 MicroPython 固件，对话框里只有官方在线固件列表，选不到本地 `firmware.bin`。

**原因**：新版 Thonny 这个对话框是「在线固件列表」形态，没有本地文件选择入口。

**解法**：放弃 GUI，走终端 esptool 烧本地 bin：

```powershell
python -m esptool --port COM4 write_flash 0x0 "<本地bin路径>"
```

烧完再回 Thonny 连板子。这是本项目最终采用的方案。

### 3. 上传 .py 后代码不生效

**现象**：在 Thonny 里改好了文件、看起来传上去了，但运行行为没变；甚至传都传不上去。

**原因**：作者给的 BLE 合体固件把 `Kang_BLE.py` 烧进了内部文件系统，**冻结模块的优先级高于用户文件系统**，你传的同名文件被覆盖忽略。

**解法**：换成官方纯净 MicroPython（v1.29.0）+ 自己上传 9 个 .py。这条路已验证走通。

### 4. .py 文件传不到板子上

**现象**：把 .py 拖到 Thonny 窗口里没反应；或者以为是直接在资源管理器拖文件。

**原因**：上传入口在 Thonny 的左侧「文件」面板，不是 Windows 资源管理器。

**解法**：Thonny 左侧文件面板 → 右键目标 .py → `Upload to /` → 选板子根目录。

## 二、硬件与接线

### 5. 原理图脚号对不上开发板引脚

**现象**：原理图上模组的脚标着 12、13、18、19…，开发板排针丝印是 0、1、2、3…，完全对不上号。

**原因**：两套编号体系。
- 原理图的数字是**模组封装机械脚号**（按顺序排的第几个焊脚）；
- 开发板丝印的数字是 **GPIO 编号**（芯片功能编号）。

**解法**：不看脚号，看**网络名**。名字相同的就连在一起：原理图 `IO4` = 板子丝印 `4`，`TXD0` = `TX`，`EN/RST` = `EN`，`3V3` = `3V3`。

### 6. 电池采样脚到底是 0 还是 1

**现象**：原理图把 `ADC_BAT` 标在 IO0，飞控代码 `Battery()` 默认 `pin=1`。两个说法冲突。

**原因**：作者原理图和固件之间没对齐。

**解法**：**以实际运行的代码为准** → 接排针 `1`（GPIO1）。
验证方式：接好后万用表量中点电压，和串口读到的电池电压×4 对比，能对上就说明脚接对了。

### 7. 多个 GND 排针，接哪个

**现象**：板子上有四五个 GND 丝印，不知道是不是都要接。

**原因**：不重要，它们是同一个地网络。

**解法**：任选一个，就近取。但**所有外接设备（舵机、降压模块、分压电阻）的地必须都汇到这同一个地网络**，缺一个地，那一路就没有参考电位。

### 8. 板载 IO8 的灯怎么点不亮

**现象**：按作者接法「GPIO8 拉低即点亮」去写代码，板载灯不亮或颜色不对。

**原因**：作者的飞控板上 IO8 挂的是普通单色 LED（共阳接法，拉低点亮）；第三方开发板上 IO8 可能是**板载 RGB 彩灯**，走单线时序协议，不是简单高低电平。

**解法**：以自己板子的实际情况为准。用普通 LED 就按共阳/共阴接法写高低电平；板载 RGB 灯要用对应的驱动库。

### 9. `.SchDocPreview` 想拿来改 PCB

**现象**：以为 `1，电路\飞控\__Previews\teach_flying_V2.0.SchDocPreview` 是工程文件，想直接在立创 EDA 里打开继续编辑、生成 PCB。

**原因**：它只是立创 EDA（专业版）的**预览缓存**，不是可编辑工程文件，不能用于设计。

**解法**：想改电路或做 PCB，只能在立创 EDA 里按原理图 PDF 重新绘制。

### 10. 电池电压直接进 ADC 脚

**现象**：想着"ADC 能测电压"就把电池正极接到排针。

**原因**：GPIO 的 ADC 输入量程只有 0–3.3V，2S 电池 7.4–8.4V 直接进去会烧脚。

**解法**：必须经分压（本项目 300k 上臂 + 100k 下臂，缩到 1/4）后再接 ADC 脚。

### 11. 电池能不能直接插开发板

**现象**：想省掉降压模块，把 2S 电池直接接到板子 5V 针或 3V3 针。

**原因**：成品开发板的稳压芯片只认 5V 输入，扛不住 7.4–8.4V。

**解法**：电池必须先经降压模块（Mini360 一类）降到 5V，再从 5V 排针进板子。3.3V 由板载 LDO 自己降，不需要你管。

## 三、认知误区（读图时最容易想错的）

### 12. "原理图里同一根电源线画了两遍，是不是接错了"

不是。原理图是**分模块画**的，靠**同名网络**（`Vbat_2S`、`GND`、`VCC`、`ADC_BAT`…）表示电气连通。名字相同即相连，哪怕画在不同页、没有画导线。真正把线连起来的是 PCB 铜箔或洞洞板飞线。

### 13. "主控模组是 ESP32-S3"

不是。飞控主控是 **ESP32-C3-MINI-1**。低清截图/SchDoc 预览里 `C3` 常被误读成 `S3`，以高清渲染和数据手册为准。两者引脚和功能差别很大，混了会接错。

### 14. "Mini360 把整个电源部分都替代了"

不是。Mini360 只替代**电池高压 → 5V** 这一级 DCDC 降压。它不替代：
- 5V → 3.3V 的 LDO（成品开发板板载已做）；
- 电池采样分压（要自己搭）；
- 舵机接口（要自己接）。

### 15. "开发板内部有电源切换和防反接保护"

一般没有。成品 ESP32-C3 开发板只做「USB 5V → LDO → 3.3V」这一条最基础的供电链，**没有**作者原理图第 8 张那套 PMOS 双路切换、肖特基防倒灌、防反接。所以：

- USB 和电池靠手动插拔切换，不自动；
- 正负极接反没有板级兜底，**接线前必须自己核对**；
- 电池不要反向灌进 USB 口。
